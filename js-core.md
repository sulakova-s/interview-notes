# 👾 JS Core — шпаргалка к собеседованиям

## 📌 Префикс и постфикс

| | Сначала | Потом |
|---|---|---|
| `++a` | прибавляет | возвращает новое значение |
| `a++` | возвращает старое значение | прибавляет |

```js
let a = 5;
console.log(++a); // 6
console.log(a);   // 6

let b = 5;
console.log(b++); // 5
console.log(b);   // 6

let x = 1;
let y = x++;
let z = ++x;
console.log(x, y, z); // 3 1 3

let c = 5;
let d = ++c + c++;
console.log(c, d); // 7 12
```

## 📌 var, let и const

| | `var` | `let` | `const` |
|---|---|---|---|
| Область видимости | функция | блок `{ }` | блок `{ }` |
| Поднятие (hoisting) | да, со значением `undefined` | да, но TDZ → `ReferenceError` | да, но TDZ → `ReferenceError` |
| Когда использовать | никогда | значение меняется | по умолчанию, хороший тон |
| Повторное объявление | да | `SyntaxError` | `SyntaxError` |
| Переприсваивание | да | да | `TypeError` |
| Изменение объекта | да | да | да |
| В цикле с `setTimeout` | одна на весь цикл → `3 3 3` | своя на итерацию → `0 1 2` | — |

- **С `var`:** переменная `i` одна на весь цикл. Функции в `setTimeout` выполняются уже после завершения цикла — так работает event loop. К этому моменту `i` уже равна 3, и все три функции читают одну и ту же переменную.
- **С `let`:** на каждой итерации создаётся новая переменная `j`. Каждая функция запоминает свою: 0, 1 и 2. Функция, которая запоминает переменные из окружения, где была создана, — это и есть замыкание.

**TDZ (temporal dead zone)** — «временная мёртвая зона»: участок кода от начала блока до строки, где объявлена переменная через `let` или `const`. Переменная там уже существует (JS поднял её объявление), но ещё не инициализирована. Любое обращение к ней в этой зоне выбрасывает `ReferenceError`.

**Почему так:** с `var` код тихо получает `undefined` и ломается где-то дальше. С `let` и `const` он падает сразу, в том месте, где ошибка.

```js
const arr = [1, 2];
arr.push(3);  // сработает
arr[0] = 100; // сработает
arr = [5, 6]; // TypeError: Assignment to constant variable
```

## 📌 Замыкание

**Замыкание** — это функция вместе с её лексическим окружением. Она запоминает переменные из места создания и имеет к ним доступ даже после завершения внешней функции. Используется для приватного состояния, фабрик функций и колбэков, в React — в обработчиках и хуках.

**Как работает:** пока функция ссылается на своё лексическое окружение (Lexical Environment), сборщик мусора (garbage collector) его не удаляет. Лексическое окружение — функция видит переменные из места, где её написали, а не где вызвали.

```js
function createCounter() {
  let count = 0;
  return () => ++count;
}

const counter = createCounter();
counter(); // 1
counter(); // 2
```

**Зачем нужно:**
- **Приватное состояние:** переменная живёт только в «рюкзаке», и менять её можно только через саму функцию.
- **Колбэки:** вызываются позже, но помнят данные из места создания.
- **Фабрики:** логику настроили один раз и переиспользуем без повторной передачи настроек.
- **React:** каждый рендер — новый вызов компонента, и функции внутри помнят state и props своего рендера.

**Stale closure:** функция запомнила state старого рендера и не видит новый.
- Причина: чаще всего `useEffect` с пустым `[]` или неполными зависимостями.
- Решение: добавить переменную в зависимости или использовать функциональное обновление `setCount(prev => prev + 1)`.

**Связь с циклом:** `let` в цикле → на каждой итерации новая переменная → у каждого замыкания свой «рюкзак» → `0 1 2`.

##  📌 Event loop: микро- и макрозадачи

**Event loop** — «менеджер», который решает, какой код выполнить следующим. JS однопоточный: в каждый момент выполняется одна задача. Физически — бесконечный цикл: когда стек пуст, берёт следующую задачу из очередей. Благодаря ему асинхронные операции (таймеры, запросы) не блокируют поток, пока выполняются.

**Участники:**
- **Call stack** — выполняет код, одну задачу за раз.
- **Web APIs** — браузерные API (`setTimeout`, `fetch`, события DOM). Работают вне основного потока JS. Когда работа готова (таймер истёк, ответ пришёл), кладут колбэк в очередь.
- **Очередь микрозадач (microtasks)** — `.then` / `.catch` / `.finally`, продолжение после `await`, `queueMicrotask`.
- **Очередь макрозадач (macrotasks)** — `setTimeout`, `setInterval`, события (клик, ввод), сообщения. Сам скрипт при загрузке страницы — тоже макрозадача.

## Порядок работы

- Микрозадачи проверяются после **каждой** задачи и выполняются **все**, включая новые, которые появились по ходу.
- Макрозадача берётся **одна** за цикл.
- Отрисовка — отдельный шаг: после всех микрозадач, между макрозадачами.

## Синхронно или нет

| Код | Когда |
|---|---|
| Тело `new Promise(...)` | сразу, синхронно |
| `async` до первого `await` | сразу, синхронно |
| После `await` | микро |
| `.then` | микро |
| `setTimeout` | макро |

## Частые вопросы

**1. Почему `setTimeout(fn, 0)` не выполняется сразу?**
Задержка — это «не раньше чем», а не точное время. Таймер истёк → колбэк в очередь макрозадач → ждёт, пока освободится стек и выполнятся все микрозадачи. Гарантировать точное время в JS нельзя.

**2. Что будет, если микрозадача бесконечно создаёт новые микрозадачи?**
Страница зависнет полностью: очередь микрозадач никогда не пустеет, поэтому цикл не доходит ни до отрисовки, ни до макрозадач (кликов, таймеров).

**3. Почему тяжёлый синхронный код «замораживает» интерфейс?**
Он занимает стек. Пока стек не освободится, event loop не может перейти к микрозадачам, отрисовке и обработке событий.

## Задача: порядок вывода

```js
console.log(1);

setTimeout(() => console.log(2), 0);

Promise.resolve().then(() => console.log(3));

new Promise((resolve) => {
  console.log(4);
  resolve();
}).then(() => console.log(5));

(async () => {
  console.log(6);
  await null;
  console.log(7);
})();

console.log(8);

// 1 4 6 8 3 5 7 2
```

**Построчное объяснение:**

| Строка | Куда | Почему |
|---|---|---|
| `1` | сразу | синхронно |
| `2` | макро [2] | таймер |
| `3` | микро [3] | `.then` |
| `4` | сразу | тело `new Promise` синхронное |
| `5` | микро [3, 5] | `.then` |
| `6` | сразу | код `async` до `await` синхронный |
| `7` | микро [3, 5, 7] | после `await` → микрозадача |
| `8` | сразу | синхронно |

Стек опустел → все микрозадачи: `3 5 7` → одна макрозадача: `2`.
