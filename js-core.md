# 👾 JS Core — шпаргалка к собеседованиям

## 📌 Префикс и постфикс

| | Сначала | Потом |
|---|---|---|
| `++a` | прибавляет | возвращает новое значение |
| `a++` | возвращает старое значение | прибавляет |

```js
let a = 5;
console.log(++a); // 6
console.log(a);   // 6

let b = 5;
console.log(b++); // 5
console.log(b);   // 6

let x = 1;
let y = x++;
let z = ++x;
console.log(x, y, z); // 3 1 3

let c = 5;
let d = ++c + c++;
console.log(c, d); // 7 12
```

## 📌 var, let и const

| | `var` | `let` | `const` |
|---|---|---|---|
| Область видимости | функция | блок `{ }` | блок `{ }` |
| Поднятие (hoisting) | да, со значением `undefined` | да, но TDZ → `ReferenceError` | да, но TDZ → `ReferenceError` |
| Когда использовать | никогда | значение меняется | по умолчанию, хороший тон |
| Повторное объявление | да | `SyntaxError` | `SyntaxError` |
| Переприсваивание | да | да | `TypeError` |
| Изменение объекта | да | да | да |
| В цикле с `setTimeout` | одна на весь цикл → `3 3 3` | своя на итерацию → `0 1 2` | — |

- **С `var`:** переменная `i` одна на весь цикл. Функции в `setTimeout` выполняются уже после завершения цикла — так работает event loop. К этому моменту `i` уже равна 3, и все три функции читают одну и ту же переменную.
- **С `let`:** на каждой итерации создаётся новая переменная `j`. Каждая функция запоминает свою: 0, 1 и 2. Функция, которая запоминает переменные из окружения, где была создана, — это и есть замыкание.

**TDZ (temporal dead zone)** — «временная мёртвая зона»: участок кода от начала блока до строки, где объявлена переменная через `let` или `const`. Переменная там уже существует (JS поднял её объявление), но ещё не инициализирована. Любое обращение к ней в этой зоне выбрасывает `ReferenceError`.

**Почему так:** с `var` код тихо получает `undefined` и ломается где-то дальше. С `let` и `const` он падает сразу, в том месте, где ошибка.

```js
const arr = [1, 2];
arr.push(3);  // сработает
arr[0] = 100; // сработает
arr = [5, 6]; // TypeError: Assignment to constant variable
```

## 📌 Замыкание

**Замыкание** — это функция вместе с её лексическим окружением. Она запоминает переменные из места создания и имеет к ним доступ даже после завершения внешней функции. Используется для приватного состояния, фабрик функций и колбэков, в React — в обработчиках и хуках.

**Как работает:** пока функция ссылается на своё лексическое окружение (Lexical Environment), сборщик мусора (garbage collector) его не удаляет. Лексическое окружение — функция видит переменные из места, где её написали, а не где вызвали.

```js
function createCounter() {
  let count = 0;
  return () => ++count;
}

const counter = createCounter();
counter(); // 1
counter(); // 2
```

**Зачем нужно:**
- **Приватное состояние:** переменная живёт только в «рюкзаке», и менять её можно только через саму функцию.
- **Колбэки:** вызываются позже, но помнят данные из места создания.
- **Фабрики:** логику настроили один раз и переиспользуем без повторной передачи настроек.
- **React:** каждый рендер — новый вызов компонента, и функции внутри помнят state и props своего рендера.

**Stale closure:** функция запомнила state старого рендера и не видит новый.
- Причина: чаще всего `useEffect` с пустым `[]` или неполными зависимостями.
- Решение: добавить переменную в зависимости или использовать функциональное обновление `setCount(prev => prev + 1)`.

**Связь с циклом:** `let` в цикле → на каждой итерации новая переменная → у каждого замыкания свой «рюкзак» → `0 1 2`.
